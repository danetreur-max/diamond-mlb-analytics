HONEST EXPECTATIONS

How wrong is the benchmark?

The full application reconstructs a weighted baseline from the previous three available seasons, using weights of 5, 3 and 1. Target-year results never enter that year’s baseline.

YearPlayersTypical error (WAR) ⓘWithin 1 WAR

What these numbers cannot establish

Salary does not imply a particular WAR obligation. WAR estimates differ across providers. Public Steamer fWAR references are kept separate from actual bWAR. Original forecast dates are not always verified. The benchmark does not adjust for age, injury or role. Players without a target-year MLB WAR record are excluded from the retrospective test, creating survivorship bias. Typical historical error is not an individual confidence interval.

BUILT END TO END

A research interface on a durable data pipeline.

01 / FRONTEND

React + TypeScript

Sortable tables, beginner metric explanations, year-over-year changes, player comparisons, contract research and browser-local review snapshots.

02 / BACKEND

FastAPI + SQLAlchemy

REST endpoints, explicit data provenance, SQLite for local use and PostgreSQL support. A public-mode policy rejects mutation requests.

03 / INGESTION

Recoverable game imports

Persistent job queue, bounded retries and per-game atomic updates. Reimports replace corrected stats without duplicate player-game records.

04 / VALIDATION

Evidence over certainty

Backend and frontend calculation tests, reproducible local performance measurements and automated demo journey tests. Missing data stays missing.

Public demo scope: Atlanta contract snapshot and historical benchmark validation. Full application: teams, players, games, leaderboards, comparisons, year changes, favorites and manual ingestion. This static demonstration does not claim to run the Python backend in the browser.
